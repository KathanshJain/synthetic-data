# Machine Learning on Artificially Forged Data

A mini-project (CSET312) by **Aryan Gupta** and **Kathansh Jain**, Bennett University.

## Project Overview (the short story)

Imagine an organisation that holds a table of personal records. It cannot share the full
table, so a team receives only a small sample. Can that team learn the patterns in the
small sample, generate extra *artificial* records, and train a model on the artificial
records that still works on real, unseen data? That is exactly what we measure. We ask:
**how much real data does a generator need?** — and we answer with a controlled
experiment, not a guess.

## Research Question

How does the size of a small real "seed" sample affect the **fidelity**, downstream
**utility**, and **privacy risk** of synthetic tabular data generated by CTGAN and
Gaussian Copula, using the Adult Census Income dataset?

## Setup

```bash
python -m venv venv
venv\Scripts\activate            # Windows
pip install -r requirements.txt
```

Note: developed and tested on Python 3.14 with **SDV 2.2** (its API takes a
`{table_name: DataFrame}` dict in `fit()` and returns one from `sample()`;
CTGAN uses `enable_gpu=...`). CTGAN may emit NaN for very rare categories
(workclass, occupation, native-country) — flagged by `validate_synthetic()`.

**Data-quality caveat on the reported results:** the full experiment was run
*before* the NaN-repair step (`repair_synthetic()` in src/generators.py) was
added, so the saved synthetic CSVs contain some NaN rows in rare categorical
columns and the reported TSTR metrics are therefore slightly pessimistic.
Current code repairs these NaNs by sampling from the real category
distribution; re-running `python -m src.run_experiment` would refresh all
results with the fix applied.

## The Backend (api/)

The React frontend talks to a FastAPI service that **wraps `src/`** — it
never re-implements the pipeline and never loads the locked test set (its
only interaction with it is `verify_test_hash()` → a verified true/false;
counts come from `manifest.json`). All numbers are served from
`results/*.csv`, `reports/report_facts.json` and `manifest.json` — nothing
is invented or estimated. Endpoints (mounted under `/api` and at the root):

| Endpoint | Serves |
|---|---|
| `GET /health` | status + cached pytest summary (results/checks.json) |
| `GET /overview` | dataset story + locked-set hash status |
| `GET /dataset/distribution?column=` | real-data distribution for one column |
| `GET /seeds` | seed sizes, random seeds, nested-split check, class counts |
| `GET /results/summary?model=` | per-arm metric means/stds |
| `GET /results/reference` | TRTR-full reference + random-guess PR-AUC |
| `GET /results/fidelity` | fidelity summary (KS/TVD/chi2/corr/coverage) + per-column |
| `GET /results/privacy` | DCR summary (median/p05/ratio/exact rates) |
| `GET /results/privacy/histogram` | DCR histogram for one run |
| `GET /results/runtime` | generator training seconds |
| `GET /results/loss-curve` | CTGAN loss trace (only exists after a `--refresh` run) |
| `GET /results/criteria` | frozen criteria rules + pass/fail table |
| `GET /compare/distribution\|correlation\|projection` | real-vs-synthetic comparisons (PCA fitted on real only) |
| `POST /lab/upload` | profile an uploaded CSV (rate-limited) |
| `POST /lab/run` | start a lab job (one CTGAN at a time; staged progress) |
| `GET /lab/jobs/{id}` + `/events` | poll or SSE-stream job status |
| `GET /lab/jobs/{id}/download` | the job's synthetic CSV |

Every error uses `{"error": {code, message, hint}}`. The frontend switches
from mock data to the live API via `frontend/web/.env`
(`VITE_USE_MOCKS=false`, `VITE_API_URL=http://localhost:8000`). The API
type contract is exported to `api/openapi.json` and rendered to
`frontend/web/src/api/types.generated.ts` with openapi-typescript.

For production, `api/main.py` also serves the built frontend
(`frontend/web/dist`) at `/`, so one process hosts everything; see
`Dockerfile` / `docker-compose.yml`.

## Results (full experiment: 3 random seeds × 5 seed sizes, locked test set)

Reference: **TRTR-full XGBoost PR-AUC = 0.823** on the locked test set.

| Seed size | TRTR-seed | SMOTE-NC | TSTR-CTGAN | TSTR-GC |
|---|---|---|---|---|
| 100 | 0.591 | 0.574 | 0.563 | 0.350 |
| 250 | 0.643 | 0.635 | 0.633 | 0.469 |
| 500 | 0.699 | 0.690 | 0.648 | 0.409 |
| 1000 | 0.733 | 0.721 | 0.619 | 0.406 |
| 2000 | 0.761 | 0.753 | 0.648 | 0.476 |

(XGBoost PR-AUC, mean over random seeds 0/1/2. Full tables: `results/RESULTS.md`.)

**Key findings (honest):**
- **No tested seed size passed all frozen criteria** — the utility ratio peaked at
  0.79 (CTGAN, 500/2000 rows) against the 0.90 threshold, and mean KS stayed at
  0.22–0.29 against the 0.10 limit. Reported as a valid experimental finding.
- CTGAN clearly beats the Gaussian Copula on utility (0.56–0.65 vs 0.35–0.48)
  and fidelity (mean KS 0.22 vs 0.40).
- TSTR never beat TRTR-seed: on this dataset, training on the small real sample
  itself remained the better small-data choice.
- **No memorisation warning**: every DCR ratio was ≥ 1.0 (synthetic rows sit
  farther from the seed than genuine holdout rows) and exact-copy rates were ~0.
- Privacy, in other words, was never the failure mode — fidelity and utility were.

Key figures: `figures/results/pr_auc_xgboost.png`, `fidelity_vs_seed_size.png`,
`dcr_ratio_vs_seed_size.png`, `real_vs_synth_*.png`.

## Limitations

One dataset, two generative models, three random seeds, DCR as a risk *indicator* (not a
privacy guarantee), no time-series support.

## Future Work
